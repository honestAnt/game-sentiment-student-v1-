# v10 训练方案：先修尺子，再谈训练（2026-09-17）

> 现役：`student_v8` + 平台前缀 + `neg_exempt` T=0.75。  
> 结论先行：**v9 系列 16 个变体的失败不是模型不行，是尺子不行。** 在扩样金标 + 改闸门定义之前，
> 任何 v10 训练都是在 1–3 条样本的噪声上做超参搜索。本轮第一优先级是评估集，不是训练。

## 1. v9 系列复盘：闸门量的不是我们要的东西

### 1.1 B站片闸门的分辨力只有 1–3 条样本

`gold_eval_v6` 的 B站片 n=390，其中**中性 357（91.5%）/ 负面 17 / 正面 16**。
「全部判中性」这个平庸基线在该片就有 **0.9154**：

| 片 | 全判中性 | v8 | v9o | v8 领先平庸 | v9o 领先平庸 | 1 条样本 |
|---|---|---|---|---|---|---|
| weibo 评论 | 0.5525 | 0.7406 | 0.7604 | +18.8pt | +20.8pt | 0.20pt |
| weibo 博文 | 0.6733 | 0.8304 | 0.8329 | +15.7pt | +16.0pt | 0.25pt |
| **B站评论** | **0.9154** | **0.9179** | **0.9231** | **+1 条** | **+3 条** | **0.26pt** |

v8 在 B站片只比「全判中性」多对 **1 条**。v9 系列围绕 B站 打的所有仗
（−2.8pt 到 +0.51pt）都是 1–11 条样本的摆动，**纯噪声**。
v9o 的「+0.51pt PASS」= 多对 2 条，不构成任何结论。

### 1.2 更糟：B站片 acc 与「抓负面」这个目标反向

各消融版在 B站片上 acc 与负召回的关系（负召回分母只有 17 条）：

| 版 | B站 acc | B站 负召回 | 闸门 |
|---|---|---|---|
| v9b | 0.8846（**最低**） | **0.412（7/17，最高）** | FAIL |
| v9j | 0.9077 | 0.294（5/17） | FAIL |
| v8（现役） | 0.9179 | 0.235（4/17） | — |
| **v9o** | **0.9231（最高）** | **0.176（3/17，垫底）** | **PASS** |

**闸门恰好选出了负召回最差的那个模型。** 原因是机械的：B站片 91.5% 是中性，
任何提升负面敏感度的改动都会在 357 条中性上产生假阳性，slice acc 必跌；
反之越偏中性 slice acc 越高。所以「B站片 acc ≥ v8」这条闸门，
**结构上禁止 B站负面能力提升**。

### 1.3 i.i.d. 实抽印证了这是假阳性

- 既有 teacher 抽检 300：v9o 0.8567 vs v8 0.8667（**−1.0pt**），头对头 v9o 独对 1 : v8 独对 4。
- 新抽 StarRocks 487（`data/validation/v9o_iid_spotcheck/candidates_487.jsonl`）：
  一致 477（97.9%），分歧 10 条经 teacher 判定 **v8 胜 6 : v9o 胜 4**。
- v9o 的两条关键漏判正是 B站负面：`iid2_bc_301881048369`（鸣潮滑行痛批）、
  `iid2_bc_310376937697`（异环抗议动员）→ 都被打成中性。

即：gold_v6 闸门 PASS ＋ i.i.d. 反而退步，**互相矛盾时应当相信 i.i.d.**，
因为 B站片闸门的有效样本量约等于 0。

### 1.4 v9o 的配方还主动丢掉了唯一能救 B站 的数据

| 语料 | B站条数 | 其中负面 |
|---|---|---|
| `v7_1`（v8 的训练底集） | 945 | 63（6.7%） |
| **round6 新标** | **353** | **191（54.1%）** |
| v9o stage1（`v9c` 混集） | 945 | 63 |
| v9o stage2（B站回放） | 945 | 63 |

round6 花成本标出来的 **191 条 B站抗议/问责负面，v9o 一条都没用上**——
因为当初为了过 B站闸门，把 round6 B站 整片从混集里摘掉了。
这是被错误闸门逼出来的错误决策。

## 2. 本轮要做的事（顺序不可换）

目标：B站片负面从 17 条提到 **~100 条**，让负召回 1 条 = 1pt 而不是 6pt。

数据源：StarRocks DWD `dwd_crawl_bili_video_comments_details`（池 62 万，
去重+排除+长度过滤后 42.3 万，排除集覆盖训练/金标/round6/两批抽检）。

**已导出并完成人工标注回收**（导出 2026-09-17；回收 2026-09-18，
`export_gold_bili_candidates.py` / `merge_gold_bili.py`，
日志 `logs/export_gold_bili_candidates.log`）：

| 集合 | 抽法 | 量 | 文件 | 用途 |
|---|---|---|---|---|
| A. iid | 纯随机（延续 v6 的 max_per_video=2 / max_per_domain=50 协议） | **300** | `data/candidates/gold_expansion_bili/bili_iid_candidates_300.xlsx` | 量**分布真实**下的 acc，可与 v6 的 B站片续接 |
| B. challenge | 抗议/问责/批评文体**定向富集** | **250** | `.../bili_challenge_candidates_250.xlsx` | **只量负召回与负面精确率**，acc 不可与 iid/v6 横向比较 |

**富集刻意不使用任何模型分数**（放弃了原计划的「v8 低置信 + 高负概率」两路召回）：
用模型不确定性挑样本，后续模型在该集合上天然占便宜，尺子就不公正了。
只用文体/词汇通道，对 v8 与 v10 是同一分布。

challenge 集通道构成（配额按价值分配，非均摊）：

| 通道 | 条数 | 说明 |
|---|---|---|
| 抗议动员 | 71 | v8 核心盲区（抽检里抗议文体高置信判中性 9/11） |
| 问责 | 70 | 指向官方/策划；`策划`(2670)/`补偿`(1989) 实测语境几乎全为投诉 |
| 显式批评 | 70 | 辱骂/差评 |
| 委婉批评 | 39 | 关键词天然圈不准，只保留高精度核 + 小配额，价值在诊断而非凑量 |

词表经 42.3 万条真实池**逐 token 审计**后定稿，剔除了游戏语境中性高频词——
这些词留着会把富集集稀释回随机集：

| 剔除词 | 命中 | 为什么是伪负面 |
|---|---|---|
| `坑` | 2708 | 退坑/回坑/入坑是中性游戏词 |
| `一起` `联合` | 2692 / 93 | 纯连词（"男声女声合一起"） |
| `要是` `本来` | 2454 / 1759 | 话语标记 |
| `希望` | 2453 | 多为期待而非批评 |
| `越来越` | 886 | 常接"越来越好" |
| `可惜` | 1204 | 多为对剧情的惋惜 |
| `烂` `屎` | 1210 / 461 | "手法烂"自嘲、"红屎"是 BOSS 外号 |
| `还不如` | — | 比较句式（"还不如21温迪"） |

已知残留假阳性（有意保留）：`垃圾队` 是配队术语会命中「显式批评」。
challenge 集本就需要混入「带负面词但实为玩梗/中性」的样本，
**否则只量到召回、量不到精确率，会鼓励模型乱判负面**。

**人工标注约定（用户 2026-09-17 拍板：走人工，不用 teacher）**：
- 两份表**分开标、分开回收**，在「人工标注-杠」列填 中立/负向/正向（或 中性/负面/正面）。
- challenge 集里玩梗/中性的请如实标中性，不要因为「这批是负面集」而倾向标负。
- 若改用 teacher(glm) 标注，gold 将退化为「蒸馏一致性检查」而非独立尺子，
  **不能再用于晋级判定**——故本轮不走 teacher。

### 步骤 B（阻塞）— 改闸门定义，先定后训

现闸门（三片 acc ≥ v8）已被证明对 B站 无效且反向。新闸门（**已拍板**）：

1. **weibo 评论 / weibo 博文**：保持 acc ≥ v8 同片（这两片平庸基线只有 0.55/0.67，
   acc 有 15–20pt 的有效信号，闸门有意义）。
2. **B站评论**：acc 闸门降级为护栏 **acc ≥ v8 − 1.0pt**，
   **主判据换成负召回 ≥ v8 同片**（在步骤 A 的 challenge 集上量，分母 ~100）。
3. **博文负召回** ≥ 0.88 保持不变。
4. **i.i.d. 抽检从「事后验证」提到「晋级必过项」**：新抽 ≥400 条，
   总 acc 不低于 v8，且 B站负面漏判不增加。v9o 就是只过 gold 不过 i.i.d.。

闸门代码已落地为唯一真源：`gold_gates.py` + `evaluate_gold_v6_gates.py`
（闸门 FAIL 时退出码 1）。改定义时只改 `gold_gates.check_gates` 与其单测
`tests/test_gold_gates.py`，不要再写一次性脚本。

### 步骤 C — v10 训练（步骤 A/B 完成后才开始）

已知有效的两件事，直接继承：
- **微博评论仪式应援 vs 直球夸赞**：v9 全系列稳定 +1.2~+2.8pt，正召回 0.556 → 0.653。
  这是真增益，round6 微博评论 531 条要保留在混集里。
- **软 LR 抑制遗忘**：lr 2e-5 → 5e-6 单调收窄跨片伤害；全量重训用 5e-6×2ep 起步。

需要新做的一件事：
- **把 round6 B站 191 条负面用上**。v9b（唯一负召回上到 7/17 的版本）证明这批数据
  确实带信号，只是当时被 B站 acc 闸门否掉。新闸门下应重跑 v9b 型配方
  （B站负面不降采样，或轻度降采样），用 challenge 集的负召回来裁决。

#### C.1 v10a：去重对照（已备料）

2026-09-17 发现 `v7_1_train_mixed.jsonl` 有 **569 行整行复制**，全来自 `lol_*`：
B站片 945 行只有 529 条唯一评论（208 条各复制 3 遍），微博评论 858 行只有 705 条唯一
（153 条各 2 遍），微博博文零重复。**B站训练片 56% 的行来自 176 条唯一的中性 LoL
电竞闲聊**，被 3× 放大的那批负面占 5.8%，低于未放大的 8.4%。

这给了 B站 中性偏置一个比学习率更硬的机制解释，也解释了 v9o 为什么负召回垫底——
它 stage2 回放的 `v9k_bili_replay_only.jsonl` 正是这份带 3× 复制的 945 行。

但**现役 v8 就是拿带复制的 v7_1 训出来的**，去重是待验证改动，不是既定修复。
`build_v10_train_mixed.py` 已产出对照料：

```bash
python build_v10_train_mixed.py              # -> data/labeled/v10a_train_mixed.jsonl
python build_v10_train_mixed.py --keep_dups  # 对照：逐行复现 v9_train_mixed（已验证）
```

| | v9j 的料 | v10a 的料 |
|---|---|---|
| 总行数 | 8095 | **7526**（−569 复制行） |
| B站片 | 1298 行 / 882 唯一 / 负面 19.6% | 882 行全唯一 / 负面 **26.1%** |
| 微博评论 | 4039 行 / 3886 唯一 | 3886 行全唯一 |
| 微博博文 | 2758 行 | 2758 行（本就无重复） |

两者语料来源、round6 全量、lr=5e-6×2ep 全同，**唯一变量是去重**，v9j 直接充当对照组。
去重把 B站 负面占比抬到 26.1%（删掉的复制行绝大多数是中性），方向上推高负召回、
压低 acc——正好由新闸门的「negR 主判据 + acc 护栏」来裁。

```bash
python train_student.py \
  --train_file data/labeled/v10a_train_mixed.jsonl \
  --init_from models/student_v8 \
  --output_dir models/student_v10a \
  --prefix_granularity platform_ct \
  --learning_rate 5e-6 --num_train_epochs 2

python evaluate_gold_v7_gates.py --model_dir models/student_v10a --tag v10a \
  --baseline data/validation/gold_eval_v7_v8_baseline.json --recipe "v7_1去重+round6全量 5e-6x2ep"
```

#### C.3 v9j 误差解剖（2026-09-18）— 下一刀对准「中性难例」

详见 `docs/v9j误差解剖-B站护栏-2026-09-18.md`；明细
`data/validation/v9j_error_autopsy/`。

相对 v8，v9j 在 gold B站片 **净少对 10 条**（回归 19 / 改进 9），护栏差 ~3 条：

| 回归类型 | n | 含义 |
|---|---|---|

目标 chNR 不掉、护栏过线；并行统一 B站轻度夸的标注口径。

## 3. 明确不做

- **不再做 LR / epoch 网格搜索**。v9i→v9j→v9m→v9o 已经把 2e-5/1e-5/5e-6/3e-6 走完，
  收益上限就在 1–3 条样本的噪声里，再扫是浪费。
