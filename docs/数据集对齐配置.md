> 快照日期：2026-09-18（gold_v7 回收；v9/v10 扫参均未晋级；**现役仍 student_v8**）。

> **v5→v8 审计结论（2026-09-15，详见 dev_state.json student_modeling.audit_v5_to_v8）**：
> ① v5 现役实为 1-epoch 欠训练模型，宽置信带 + T0.75 回退是共适应拐杖，后续充分训练模型必然置信上移、拐杖失灵——四轮不晋级的系统级根因，晋级判据改为「端系统（模型+工作点）在 i.i.d. 上验证」；
> ② v8 博文「变差」大部分是假象（博文 raw 0.8130 > v5 0.7980），真凶是一刀切回退摧毁低置信真负面（28/85）；
> ③ 非对称回退（负面不回退）= v8 正确工作点候选：gold 总 0.8495 / 博文 0.8304 / B站 0.9179 / 负召回 0.882 / macro_f1 0.7339 史上最高，holdout 不反对（0.6650 > v5 任意点）；**2026-09-15 用户拍板直接晋级 v8+豁免**（raw vs 豁免的最终取舍留待 i.i.d. 抽检，切换成本仅一个 flag）；
> ④ 已排除：截断（512 重推零差异）、泄漏、博文先验失配、claude 重标削弱负面、标签质量；
> ⑤ 人标池枯竭：双盲未人标评论 889/1000 被 round4 占用，仅余 15，扩样须新源。**已解（2026-09-15）**：两批导出——LoL 评论 CSV 同源 220（评论片去噪）+ **StarRocks 多游戏源 220**（凭证只放本地环境变量；多游戏在 DWD 平表，连接信息见 `.env.example`。当时单库微博 hashtag 几乎全是 LoL，原始层是 payload JSON）；**同构的小样本爬虫源弃用**；**品牌域批（示例品牌 200 条）导出后放弃——非游戏域不硬塞进判据**。DWD 平表同时是下轮训练数据的多游戏拉取通道。公开仓库不含这些原文。

> 下游 `v9/v9b/v9c_train_mixed` 全部继承了这 569 行。

> **晋级闸门口径（2026-09-17 起）**：唯一真源 `gold_gates.py`。
> `GATES_V6` = 历史三片 acc 闸门（保留用于复现 v9 系列，已证伪见下）；
> `GATES_V7` = 新口径，共 5 条：微博两片 acc ≥ 基线、博文负召回 ≥ 0.88（绝对下限）、
> **B站 acc 降级为护栏（≥ 基线 − 1.0pt）、B站负召回（在富集集上量）升为主判据**。
> 评估入口 `evaluate_gold_v7_gates.py`（双集合，闸门 FAIL 退出码 1）。
> 回收入口 `merge_gold_bili.py`（iid 并入 gold_v7；challenge 独立落盘**不进 gold**）。

> **B站片闸门失效（2026-09-17 定案）**：`gold_eval_v6` B站片 n=390 中中性 357（91.5%），
> 「全判中性」平庸基线即 0.9154——v8（0.9179）只比它多对 **1 条**，v9o（0.9231）多对 3 条，
> 该片闸门的有效分辨力约等于 0（1 条 = 0.26pt）。且方向反了：全系列里负召回最高的 v9b（7/17）
> B站 acc 最低并 FAIL，而 acc 最高、闸门 PASS 的 v9o 负召回垫底（3/17 < v8 的 4/17）。
> 机制上，B站负面敏感度提升必在 357 条中性上产生假阳性 → slice acc 必跌，
> 因此「B站片 acc ≥ v8」**结构上禁止 B站负面能力提升**。
> 结论：扩样 B站负面（17 → ~100）并改闸门定义后才能再训。方案见
> `docs/v10训练方案-先修尺子-2026-09-17.md`；闸门代码唯一真源 `gold_gates.py`。

## 四、采样与混训的对齐规则（经验沉淀）

1. **负面占比目标 21–26%**：teacher 标完若 >26% 触发 `downsample_by_label`（v2→v3 实证 +2pt）。round2 的 44.6% 负面是先验漂移教训。
2. **平台三分片配额**（放量默认）：B站评论 40% / weibo评论 30% / weibo博文 30%（博文必须有有意义配额，round3 试标仅 8 条博文导致评论信号泄漏）。
3. **候选行字段规范**：`id / text / platform / content_type / source_table / content_hash` 六字段齐全；标注行再追加 `final_label / final_emotion / reason(≤20字) / teacher`，text 逐字节不改写。
4. **标注口径**：游戏域以 `prompts/glm_teacher_shard_round6.md` 为准（round4 的分片口径 + 微博评论短应援=正面）；最高优先级「拿不准判中性」。B站直球应援=正面、玩梗=中性；weibo博文仪式应援=中性、评论直球夸/加油/打call=正面。
5. **混训底线**：新混合集与上一版做 id 去重断言；**v9 起评估只在 gold_eval_v6 上做**（v8 晋级数字仍报 v5 以便历史可比）；阈值类结论必须用 i.i.d. 留出/抽检（gold_v6 中性仍 69.9%，会高估回退到中性的收益）。金标永不进 `train_student.py`。
6. **架构前提（v6/v7 两次实证）**：单模型无 platform 特征，微博问责黑话（负面）与B站玩梗（中性）必然互相干扰——继续加通用数据不会涨点。若做 platform 特征输入或分平台模型，训练语料直接用上表已标注集全集重训，不需要新标注。
