# 游戏舆情情感分析：LLM 蒸馏 BERT 技术宣讲

> 仓库：`game_sentiment_project`  
> 版本：第一轮 `student_v1` 已落地；第二轮 LoL 主动学习进行中  
> 受众：算法 / 数据 / 业务研发  
> 时长建议：25–30 分钟（含 Q&A）

---

## 0. 一句话结论

**大模型只负责把训练集标对，不进生产。生产跑 110M 的中文情感 BERT，靠标注质量和主动学习补体量差。**

目标场景：B 站 / 微博 / 小红书 / 抖音的游戏相关文本，日增量约 **60 万–200 万** 条。线上需要稳定的三分类（负面 / 中性 / 正面），延迟和成本都不能按大模型计。

## 1. 背景：业务要什么、现有方案卡在哪

### 1.1 业务诉求

舆情侧真正要稳定输出的是「这条内容对游戏/运营是夸、骂、还是没态度」，用来做日报、告警、品类对比。细粒度情绪（愤怒、失望、期待）有分析价值，但不是主链路的硬指标。

文本特点与通用情感语料差得很远：

| 现象 | 例子 | 对模型的坑 |
|---|---|---|
| 阴阳怪气 | 「这波运营真是绝了」 | 字面褒义、真实负面 |
| 极短评论 | 「1」「来了」「含金量」 | 几乎没有语义，要靠圈层习惯 |
| 游戏黑话 | 「典中典」「下头」「急急急」 | 通用情感模型没见过 |
| 官方通稿 vs 评论 | 赛程公示 vs 弹幕嘲讽 | 同样长度、完全不同的标签分布 |
| 灌水 / 引流 | 「沙发」「求关注」 | 必须压成中性，否则污染负向告警 |

### 1.2 现成方案为什么不够

1. **直接上大模型推理**  
   日均百万级调用，成本和延迟都扛不住；还要把密钥、限流、降级做成生产系统。

2. **直接用阿里云历史极性当训练集**  
   库里已有 `sentiment_aliyun_request` / `result`。抽查后发现阿里云在这批微博上 **正性偏差很大**：去重后负向 unique 只剩约 236 条；GLM 与阿里云在 round1 的 3000 条上一致率只有 **28.4%**，最大错位是「阿里云标正面 → teacher 标中性」（1189 条）。把阿里云当金标，学生会学成「什么都往正面靠」。

3. **通用情感 BERT 开箱即用**  
   底座 `Erlangshen-Roberta-110M-Sentiment` 见过通用中文情感，但没见过游戏圈阴阳和赛事黑话。必须用领域标注再微调。

4. **人工全量标注**  
   日增百万，存量更大。标注预算只能砸在「模型最不会」的那一小撮上。

### 1.3 本项目实际走到哪一步

| 阶段 | 状态 | 关键产物 |
|---|---|---|
| 方案与脚本骨架 | 完成 | `teacher_labeling.py`、`train_student.py`、`infer_batch.py` |
| StarRocks 抽样 + GLM 分片打标 | 完成 | 3000 条 `round1_labeled.jsonl` |
| 学生模型 v1 | 完成 | `models/student_v1` |

| LoL 评论主动学习 | 进行中 | 2000 条候选已抽出，标注 20 分片中 |

## 2. 为什么做蒸馏，而不是别的路

核心判断：**蒸馏上限由标签质量决定，不由学生模型参数量决定。**

### 2.1 角色分工

```
Teacher（GLM-5.3 / 可选 Qwen+DeepSeek）
    └── 只在离线、小流量上打标
Student（Erlangshen-Roberta-110M）
    └── 只在线上、大流量上推理
```

Teacher 贵、准、慢；Student 便宜、够用、快。中间用「高置信标签 + 校验」把知识压进分类头。

### 2.2 五条设计取舍（宣讲时重点讲）

**① 主任务只做三分类，不做细粒度情绪头**

生产要可解释、可统计。情绪细类（愤怒 / 失望 / 期待…）写在标注字段 `final_emotion` 里，**不进 BERT loss**。类别一细，每类样本立刻不够，主极性会学飘。

**② Teacher 标签必须可审计，不能「一个模型标完就算」**

仓库里留了两条 teacher 路径：

- 设计稿路径：Qwen + DeepSeek 交叉，只保留一致样本，不一致进 `needs_review/`
- 本轮落地路径：Cursor × GLM-5.3 CodePlan 分片标注，用固定 prompt + JSON 校验 + 人工抽查代替双模型交叉

两条路的共同点：**写入训练集的每一行都有 `id` 可回表，text 禁止被模型改写。**

**③ 学生用 110M base，不用 large**

日吞吐 150 万–200 万时，base 在 GPU 批处理上速度优势明显。精度差在实践里往往小于「数据脏不脏」。large 留给有 A/B 证据再升级。

**④ 阿里云极性只做抽样层和对照报表，永不进 loss**

抽样时用它保证负向稀缺样本被抽全；训练时只吃 GLM 的 `final_label`。对照报表用来回答「我们相对云厂商改了什么方向」。

**⑤ 金标永远不进训练**

401 条人工标注是长期回归测试集。拿去微调会把「尺子」揉进模型，以后无法判断是真进步还是背答案。

- **标注结果**多 `final_label, final_emotion, reason, teacher`  
  BERT 只读 `final_label`。

## 4. 标签体系

```
LABEL2ID = {"负面": 0, "中性": 1, "正面": 2}
EMOTION_TAGS = ["愤怒", "失望", "无聊", "期待", "惊喜", "无关/灌水", "其他"]
MAX_SEQ_LEN = 256
```

判定口径（Teacher 和金标共用，写在 prompt 里）：

- **正面**：认可、喜爱、推荐、期待、满意、应援、中奖感谢
- **负面**：批评、失望、愤怒、抱怨、嘲讽、阴阳
- **中性**：事实陈述、提问、攻略、官方公示、灌水、引流、账号交易

两条容易讲错、必须写进说明书的规则：

1. 反讽看真实态度，不被字面褒义词骗。  
2. 与游戏无关但文本本身有情绪（伤感语录）→ 按文本极性；纯广告/科普长文 → 中性 + `无关/灌水`。

序列长度从 128 提到 **256**：微博博文去重后约 18% 超过 128 字，截断会丢掉后半段吐槽。

## 5. 语料准备

### 5.1 清洗原则

`clean_text` 只做两件事：去掉 URL、合并空白。不过度清洗。  
「???」「哈哈哈哈哈」、emoji、`[doge]` 往往就是阴阳或正面的线索。

去重键：round1 用库内 `content_hash`；round2 用清洗后文本的 MD5。长度 &lt; 2 直接丢。

### 5.2 第一轮：StarRocks 分层抽样（冷启动）

数据源（库 `example_sentiment`）：

| 表 | 行数 | 用途 |
|---|---|---|
| `sentiment_aliyun_request` | 19422 | 待用文本 |
| `sentiment_aliyun_request_result` | 40530 | 阿里云历史极性，仅分层 |
| 来源表 | 博文 16072 / 评论 3350 | 微博 only |

清洗去重后约 **13665** 条 unique。阿里云约定：`1` 正面、`2` 中性、`3` 负面。负向 unique 极少，所以抽样策略是 **负向全收，而不是按比例随机**。

实际抽出 **3000** 条（seed=42，30 片 × 100）：

| 维度 | 配额 / 实际 |
|---|---|
| 评论 | 目标 1000，实际 1000 |
| 博文 | 2000 |
| 阿里云负向层 | 全部 236 |
| 阿里云中性层 | 800 |
| 阿里云正面层 | 1964（补齐） |
| 长度桶 | 短 ≤20 / 中 21–128 / 长 &gt;128，在博文、评论内部尽量铺开 |

核库闸门：`request` 行数必须落在 `[15000, 25000]`，否则中止导出，防止连错库还静默训练。

命令：

```bash
python export_starrocks_candidates.py --output-dir data/candidates/round1
```

### 5.3 Teacher 打标（本轮落地）

每个分片开一轮 Cursor × GLM-5.3 CodePlan：

1. 打开 `prompts/glm_teacher_shard.md` + `shard_XX.jsonl`
2. 写出 `data/labeled/round1/shard_XX.jsonl`
3. 行数 = 100，原 `id` / `text` 原样带回

`validate_labeled_shards.py` 检查：JSON 可解析、行数与 id 顺序一致、`final_label` ∈ {正面, 负面, 中性}、text 未被改写。失败分片整份进 `needs_review/`，**不合并**。有效标注 &lt; 2000 拒绝开训。

round1 **30/30 分片全部通过**，合并后：

| 极性 | 条数 | 占比 |
|---|---|---|
| 中性 | 1732 | 57.7% |
| 负面 | 777 | 25.9% |
| 正面 | 491 | 16.4% |

情绪字段分布（不进训练，供抽查）：无关/灌水 1164、其他 1042、失望 430、愤怒 301。说明这批微博里灌水和「没态度」很多，teacher 没有把它们硬标成正负——这和阿里云的正性偏差正好相反。

### 5.4 第二轮：LoL 评论主动学习（当前）

`student_v1` 在人工金标**博文**上负面召回尚可，但在英雄联盟赛事评论（阴阳、短句、黑话）上，相对 agent 负向召回大约只有 **40%**。漏例多数是 **高置信中性**，不是决策边界模糊。只挖 `confidence < 0.6` 会漏掉这批「错得很自信」的样本。

原始 CSV：

- 评论约 10.9 万行，清洗去重后约 6.0 万 unique
- 官方号「英雄联盟赛事」博文 3096 条（通稿，本轮上限 10%）
- 与 round1 文本几乎不重叠

难例定义（`sampling.is_hard_example`）：

```text
confidence < 0.6
  或  预测为中性 且  P(负面) ≥ 0.20
```

抽样：总量 2000，70% 难例，官方博文 ≤10%，其余 30% 从高置信按预测类别铺开，防止简单样本退化。实际导出结果：**2000 条全部是评论**（官方博文 0，低于上限），hard=1400；学生预标中性 1214 / 负面 369 / 正面 417。

round2 说明书 `prompts/glm_teacher_shard_round2.md` 专门加强：`[doge]`、`是吧`、`含金量`、`我服了` 等贬义/阴阳一律负面。

当前进度：20 个分片已导出，标注完成 2/20。标完后与 round1 混合，从 `student_v1` 继续训 `student_v2`。

## 6. 金标数据：尺子怎么做、怎么用

### 6.1 来源与清洗

来源是「微博情感双盲对比」Excel，名义 2000 条。真正有人工标签的只有 **401 条**（列 `人工标注-杠` 非空），其余 1599 条是模型输出，**绝不能当 gold**。

`prepare_validation_gold.py` 做了三件必须显式做的事：

1. 只保留人工列非空的行  
2. 标签命名归一化：中立→中性、负向→负面、正向→正面  
3. 打印类型分布和类别缺口，防止误以为验证集全面

落地文件：`data/validation/validation_gold.jsonl`

| 项 | 值 |
|---|---|
| 条数 | 401 |
| 内容类型 | **全部是博文，0 条评论** |
| 中性 | 270 |
| 负面 | 85 |
| 正面 | 46 |

因此：这份尺子只能评价「微博博文」；评论、LoL 黑话必须另补 gold。正面只有 46 条，该类 F1 **仅供参考**。

### 6.2 金标的两个用法

**用法 A：验 Teacher prompt（大规模打标之前）**

```bash
python evaluate_teacher_labeling.py \
  --input data/validation/validation_gold.jsonl \
  --output data/validation/validation_predictions.jsonl
```

看三个数：Qwen vs 人工、DeepSeek vs 人工、**两模型一致子集 vs 人工**。最后一个才是会进训练集的质量。设计阈值：一致子集吻合度低于约 85%，先改 prompt，不上量。

**用法 B：验 Student（每轮训练之后，固定命令）**

```bash
python evaluate_student_on_gold.py --model_dir models/student_v1
```

gold **永不**传入 `train_student.py`。

### 7.2 难例判定：不只看最高概率

```136:142:sampling.py
def is_hard_example(conf, pred, p_neg, ...):
    if float(conf) < conf_th:          # 默认 0.6
        return True
    return pred == "中性" and float(p_neg) >= p_neg_th   # 默认 0.20
```

第二项专门打「高置信中性、但负面概率并不低」的阴阳。round1 漏召回就是这类。

```29:42:infer_batch.py
            confidences, preds = probs.max(dim=-1)
```

CUDA 上 `model.half()`。`confidence < 0.6` 的行写入下一轮候选。GPU 批处理是为日百万吞吐准备的；本机 MPS 评估时 batch 降到 16。

### 7.8 分发

`share_student.py` 打 zip：`config.json` + tokenizer + `model.safetensors` + `run_student.py`。对方不必克隆本仓库，可完全离线：

```bash
python run_student.py --model . --text "这游戏太坑了" --local-files-only
```

## 8. 训练过程与第一轮结果

### 8.1 超参

| 项 | 值 |
|---|---|
| 底座 | IDEA-CCNL/Erlangshen-Roberta-110M-Sentiment（BERT，110M，vocab 21128） |
| 数据 | round1 3000 条 GLM 标签，10% 分层验证 → 训练约 2700 / 验证 300 |
| epoch | 4 |
| 学习率 | 2e-5，weight decay 0.01 |
| 有效 batch | 64（MPS 上 8 × accum 8） |
| 序列长度 | 256 |
| 选模 | 验证集 macro-F1，`load_best_model_at_end` |
| 设备 | Apple MPS（本轮） |

训练约 168 step。loss 从约 0.99 降到后期 0.4 左右。最佳 checkpoint 是最后一轮 `checkpoint-168`。

### 8.2 验证集（300 条，来自 GLM 标签的 hold-out）

| epoch | accuracy | macro-F1 | F1 负面 | F1 中性 | F1 正面 |
|---|---|---|---|---|---|
| 1 | 83.7% | 0.805 | 0.808 | 0.875 | 0.731 |
| 2 | 83.7% | 0.803 | 0.805 | 0.878 | 0.725 |
| 3 | 83.3% | 0.800 | 0.792 | 0.876 | 0.731 |
| **4（采用）** | **84.0%** | **0.809** | **0.803** | **0.880** | **0.745** |

读法：中性最好做，正面最弱（训练集正面只有 491 条）。macro-F1 没有在中途过拟合崩掉。

### 8.3 人工金标（401 条博文，训练未见过）

| 指标 | 数值 |
|---|---|
| accuracy | **79.6%** |
| macro-F1 | **0.74** |
| 负面召回 | **94%（80/85）** |
| 正面 F1 | 0.54（仅 46 条，参考） |

主要误差是 **中性被判成正面或负面**（灌水、鸡汤、抽奖感谢的边界）。对舆情告警来说，宁可中性误伤，也不希望漏骂——当前负面召回是符合这个偏好的。

验证集 84% vs 金标 80% 的落差，一部分来自「学生在学 GLM 的口径」，一部分来自金标全是博文、且类别更偏中性。这正好说明：**不能只用 teacher 自己的 hold-out 当上线依据。**

### 8.4 Teacher 相对阿里云改了什么

同一 3000 条上，GLM vs 阿里云一致率 **28.4%（851/3000）**。

混淆矩阵里数量最大的几格（行=阿里云，列=GLM）：

| 阿里云 → GLM | 条数 |
|---|---|
| 正面 → 中性 | 1189 |
| 正面 → 负面 | 457 |
| 中性 → 中性 | 439 |
| 正面 → 正面 | 318 |
| 中性 → 负面 | 226 |

结论可以对外讲成一句话：**云厂商这批标签偏「正面」，我们的 teacher 把大量灌水、通稿、无态度文本改回了中性，并把阴阳改回了负面。学生学的是后一套口径。**

## 9. 后续微调与升级路线

按「先补数据、再动结构」排优先级。

### 9.1 立刻做：round2 → `student_v2`

1. 把剩余 18 个 LoL 分片按 `glm_teacher_shard_round2.md` 标完  
2. `validate_labeled_shards.py` 合并 `round2_labeled.jsonl`  
3. 与 round1 **混合**（不要只拿 2000 条难例接着训，否则简单样本会忘）：

```bash
cat data/labeled/round1_labeled.jsonl data/labeled/round2_labeled.jsonl \
  > data/labeled/round2_train_mixed.jsonl

python train_student.py \
  --train_file data/labeled/round2_train_mixed.jsonl \
  --output_dir models/student_v2 \
  --init_from models/student_v1 \
  --val_ratio 0.1

python evaluate_student_on_gold.py --model_dir models/student_v2
```

4. 另备一份 **LoL 评论金标**（哪怕 200–400 条人工），否则 round2 的收益在现有 401 条博文 gold 上看不出来。

### 9.2 滚动机制（每周 / 每两周）

```
日增量 --infer_batch--> 低置信 + 「中性且 P(负)≥0.2」
        --teacher 标几 k 条--> 混入历史训练集
        --init_from 上一版--> student_vN+1
        --固定 gold 回归--> 不降才上线
```

阈值 `LOW_CONFIDENCE_THRESHOLD=0.6` 是起点：挑出来太多就提高，漏难例就降低，或维持 0.6 但加上 round2 那种「中性但负面概率不低」规则。

### 9.3 Teacher 侧升级

- 预算允许时，对 round2 难例再跑 Qwen+DeepSeek 交叉，只保留双模型一致的行，进一步压标签噪声  
- 在 401 gold 上固定跑 `evaluate_teacher_labeling.py`，prompt 一改就能知道有没有伤到博文口径  
- `teacher_labeling.py` 可补 token 用量统计，给每轮标注算成本

### 9.4 学生侧升级（有证据再动）

| 方向 | 何时考虑 |
|---|---|
| 分类头 class weight / focal loss | 正面长期 F1 上不去，且确认不是缺数据 |
| 多任务：主极性 + 情绪细类 | 主链路稳定、`final_emotion` 积累够 |
| large 版 Erlangshen | 小流量 A/B 证明精度差值得吞吐损失 |
| INT8 / TinyBERT 再蒸馏 | 110M 吞吐仍不够 |
| 评论专用 gold + 分类型报表 | 现在金标 0 条评论，这是最大评估盲区 |

### 9.5 明确不做的事

- 不把阿里云极性、agent 的 1600 条伪标签当金标训练  
- 不把 401 人工 gold 混进 `train_file`  
- 不在生产路径调 LLM  
- 不把数据库密码、API Key 写进 jsonl / prompt / 文档

1. **问题**：游戏舆情日百万、阴阳黑话多；云厂商标签偏正、大模型推理太贵。
