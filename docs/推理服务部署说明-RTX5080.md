# 推理服务部署说明（RTX 5080）

> 更新日期：2026-09-15 ｜ 现役模型：student_v8 + 平台前缀 + 非对称置信回退（负面豁免）T=0.75
> 交付物：`Dockerfile` + `infer_batch.py`（离线批量）+ `infer_api.py`（在线 HTTP API）+ 本文档

镜像为双入口（`entrypoint.sh` 分发）：`batch` 走批量推理，`api` 起在线服务。两种模式共用同一模型、同一前缀与回退口径，结果字段一致。

**v8 工作点速览**（详见 docs/数据集对齐配置.md 审计小节）：
- 输入文本前拼受限平台前缀（`platform_input.py` 唯一真源）：批量模式读 CSV 的 `platform`/`content_type` 列（缺失按 `[未知]` 兜底）；API 模式请求体可选传 `platforms`/`content_types` 数组。**传错平台会让模型按错误口径判**，调用方须尽量提供。
- 非对称回退：`conf<0.75 且 pred≠负面` 改判中性，负面判定豁免（v8 低置信带含大量真负面，一刀切回退会摧毁负召回）。gold 总 0.8495 / 负召回 0.882 / macro_f1 0.7339 均为历版最高。
- 回退旧模型：`MODEL_DIR=models/student_v5 NEG_EXEMPT=0`（前缀 auto 对非 v8 目录自动关闭，旧口径数字可复现）。

## 一、机器与驱动要求

| 项目 | 要求 | 说明 |
|---|---|---|
| GPU | RTX 5080 16GB | Blackwell 架构，compute capability 12.0（sm_120） |
| NVIDIA 驱动 | ≥ 570.26 | 需支持 CUDA 12.8；`nvidia-smi` 右上角显示的 CUDA Version ≥ 12.8 即可 |
| Docker | ≥ 24 | 配合 nvidia-container-toolkit 暴露 GPU |
| nvidia-container-toolkit | 必装 |宿主机装好后 `docker run --gpus all` 才能用卡 |
| 磁盘 | 镜像约 4GB + 模型 0.5GB + 当日数据 | 60–200 万条 CSV 约几 GB，输出 jsonl 会更大（含置信度） |

宿主机就绪自检（两条都通过再继续）：

```bash
nvidia-smi                                                      # 驱动版本 ≥ 570，CUDA Version ≥ 12.8
docker run --rm --gpus all nvidia/cuda:12.8.0-base-ubuntu22.04 nvidia-smi
```

## 二、为什么 torch 必须用 cu128 轮子

RTX 50 系（sm_120）的内核只包含在 CUDA 12.8 及以后构建的 PyTorch 里。Dockerfile 里已固定
`torch==2.7.1+cu128`（从 PyTorch 官方源安装），不要改成默认源的 cu121/cu124 版本，否则首次推理即报：

```
RuntimeError: no kernel image is available for execution on the device
```

如果未来升级 torch，保持 `+cu128`（或更新的 cu129+）后缀即可，代码无需改动。

## 三、构建镜像

```bash
cd game_sentiment_project
docker build -t sentiment-infer:v8 .          # GPU 机器（RTX 5080）
docker build -f Dockerfile.arm -t sentiment-infer:v8-arm .   # 本地 macOS (Apple Silicon) 测试
```

依赖已锁定为与开发环境一致：torch 2.7.1+cu128 / transformers 4.46.3 / tokenizers 0.20.3 /
pandas 3.0.5 / numpy 1.26.4 / fastapi 0.141.1 / uvicorn 0.52.4。镜像内只包含推理代码，
模型和数据通过 volume 挂载，换模型版本不用重新 build。

**ARM 镜像（Dockerfile.arm）**：给本地 macOS 开发/联调用。macOS 容器没有 GPU 直通，
纯 CPU 推理（torch 换成 PyPI 的 aarch64 CPU 轮子，镜像小 2GB+）；除 torch 构建后缀外
依赖版本、代码、batch/api 双入口与 GPU 镜像完全一致。2026-09-14 实测（M 系 8 核容器）：
批量与 API 均约 **4–5 条/秒**（200 条 42–54s，首条含约 1s 预热），结果与开发环境逐位一致；
只够冒烟测试和接口联调，别拿来跑日增量。用法把镜像名换成 `sentiment-infer:v8-arm`、
去掉 `--gpus all` 即可，其余命令不变。

## 五、运行批量推理（离线，日增量主链路）

输入 CSV 需包含 `text` 列（UTF-8），建议带 `id` / `platform` / `content_type` 列
（platform 缺失补 unknown，content_type 缺失按 `[未知]` 前缀兜底——**前缀是 v8 判定口径的一部分，
能提供就提供**）。

```bash
docker run --gpus all --rm \
  -v $PWD/models:/app/models \
  -v $PWD/data:/app/data \
  sentiment-infer:v8 batch \
  --model_dir models/student_v8 \
  --input data/raw/daily_20260915.csv \
  --output data/predictions/daily_20260915.jsonl \
  --review_output data/candidates/lowconf_20260915.jsonl \
  --conf_threshold 0.75 \
  --neg_exempt \
  --batch_size 256
```

输出列：`predicted_sentiment`（回退后终判）、`raw_sentiment`（原始 argmax，供审计）、
`confidence`；`--neg_exempt` 开启非对称回退（v8 工作点，负面判定不回退；目录名版本号 ≥ v8 时
前缀自动启用（v9/v10… 同样命中），`--prefix off` 可强制原文）。`--conf_threshold 0` 可关闭回退。
`review_output` 是低置信候选池（conf<0.6），滚动送 teacher 标注，闭环不中断。

## 六、在线 API 服务（逐条/小批量实时调用）

### 启动

```bash
docker run --gpus all -d --name sentiment-api -p 8000:8000 --restart unless-stopped \
  -v $PWD/models:/app/models:ro \
  -e MODEL_DIR=models/student_v8 \
  -e CONF_THRESHOLD=0.75 \
  -e NEG_EXEMPT=1 \
  -e MAX_BATCH=256 \
  sentiment-infer:v8 api
```

环境变量：`MODEL_DIR`（默认 models/student_v8）、`CONF_THRESHOLD`（默认 0.75）、
`NEG_EXEMPT`（默认 1，非对称回退；回退旧模型设 0）、`PREFIX`（默认 auto=目录名版本号 ≥ v8 即开）、
`MAX_BATCH`（单次请求上限，默认 256）、`BATCH_SIZE`（内部推理批，默认 256）、`PORT`（默认 8000）。

### 接口

**GET /health** — 存活检查 + 配置回显（模型路径/设备/阈值/前缀/豁免）。

**POST /predict** — 批量预测，与批量模式同一前缀与回退逻辑：

```bash
curl -s -X POST http://<host>:8000/predict \
  -H "Content-Type: application/json" \
  -d '{"texts": ["加油啊加油！！", "捞批捞实至名归"],
       "platforms": ["weibo", "bilibili"], "content_types": ["博文", "评论"]}'
```

```json
{
  "count": 2,
  "threshold": 0.75,
  "elapsed_ms": 18.3,
  "results": [
    {"predicted_sentiment": "中性", "raw_sentiment": "中性", "confidence": 0.925, "fallback_applied": false},
    {"predicted_sentiment": "正面", "raw_sentiment": "正面", "confidence": 0.8892, "fallback_applied": false}
  ]
}
```

字段：`predicted_sentiment` 终判（含回退）、`raw_sentiment` 原始判定、`confidence` 置信度、
`fallback_applied` 是否命中回退条件（调用方可据此把 true 的样本送人工/teacher 复核）。
`platforms` / `content_types` 请求级可选数组，与 texts 等长（不等长返回 400），不传该条按
`[未知]` 前缀兜底。`threshold` 请求级可选，不传用服务端配置；空列表 / 阈值越界 / 超 MAX_BATCH
返回 422。交互式文档在 `http://<host>:8000/docs`（Swagger UI）。

### 使用注意

- **单进程部署**（不要 `--workers N`）：多 worker 会各自加载一份模型分显存，且 110M 模型单进程吞吐足够（GPU 上单批毫秒级）；在线大流量请走批量模式；
- 高峰建议调用方攒小批（如 32–128 条/请求）而不是逐条调，padding 效率更好；
- API 模式不落盘，低置信回流由调用方按 `fallback_applied`/`confidence < 0.6` 自行收集；日增量的回流闭环仍由批量模式的 `review_output` 承担。

## 七、吞吐与调优

- 模型是 110M 的 BERT，seq_len=256 截断 + FP16（脚本在 cuda 下自动 `model.half()`）。
  5080 上 batch 256 的吞吐预计在数千条/秒量级；日均 60–200 万条对应均值仅需 7–24 条/秒，
  **一张 5080 跑当日增量预计几分钟到十几分钟**，余量很大。
- 想再提速：`--batch_size 512`（16GB 显存完全够，评论平均 <50 token，padding 主导开销）；
  极端追求吞吐可把 `MAX_SEQ_LEN` 降到 128（config.py:37，评论场景实测够用），但改后需重跑金标对比确认无回归。
- 若批次里混有长博文，建议按平台分文件跑：长文本会抬高同 batch 的 padding 长度拖慢整体。

## 九、常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| `no kernel image is available...` | torch 不是 cu128 构建 | 按第二节重装/重 build |
| `CUDA driver version is insufficient` | 宿主机驱动 < 570 | 升级 NVIDIA 驱动 |
| 容器看不到 GPU | 未装 nvidia-container-toolkit 或没用 `--gpus all` | 装 toolkit，重启 docker daemon |
| 首次运行卡住尝试联网 | transformers 拉取 hub 资源 | 镜像已设 `HF_HUB_OFFLINE=1`，若自行改 Dockerfile 需保留 |
| 显存 OOM | batch 过大 + 长文本混批 | 降 `--batch_size` 或按平台拆文件 |
