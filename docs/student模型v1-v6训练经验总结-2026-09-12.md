> **续篇**：v7–v8 晋级与 v9 消融见飞书 [经验总结 wiki](https://wcn3zcdy0nuu.feishu.cn/wiki/KOIfwvOxkiONgNkdLR2covRLnjg)；**v9o 之后 → v10c** 见 `docs/student模型v9o之后-v10训练经验总结-2026-09-20.md`（2026-09-20 起现役为 `student_v8`）。

## 二、采样踩坑：主动学习把先验采歪了

**坑（v2）**：round2 用 70% 难例配额（低置信 OR 判中性且负面概率≥0.2），采出负面占比 **44.7%**（真实分布约 21%）。混训后 v2 在真实任务上准确率 84% → 79%——蒸馏数据翻倍，效果反降。

**根因**：难例挖掘天然富集边界样本，而边界样本（锐评/阴阳/玩梗）在当时的口径下大量被判负面；直接混训等于把「负面很多」这个假先验教给学生。

**修复（v3 起）**：
- 难例配额降到 30%，且只收 conf<0.6 的低置信样本（删掉「捞负面」条件）；
- 平台分层随机 70% 兜底真实分布；
- 标注后若负面 >26% 自动降采样再混训（v2→v3 实证 +2pt）；
- 试标 300 条先行闭环验证先验（修正后负面 17.3%，健康）。

## 三、标注口径踩坑：teacher 的错会原样蒸馏给学生

**坑 1（v2）：仪式化应援误标正面。** round2 的 prompt 写了「应援→正面」，224 条点赞/打call 仪式类评论被标成正面，导致学生把「仪式应援」也判正面，先验进一步漂移。修复：逐条复核改为中性（weibo 博文口径：官方战报/喜报/晋级均中性），并确立最高优先级规则「**拿不准判中性**」压制蒸馏噪声。

**坑 2（round1）：伤感语录误标负面。** 26 条无明确批评对象的伤感语录被判负面。修复：负面→中性；且只翻伤感语录，励志/深情语录保持正面——模式级批量翻转必须限定到无歧义子类。

**坑 3：平台条件口径相反。** 同样的「T1 fighting!」，B站口径=正面（直球应援），weibo 博文口径=中性（仪式应援）；B站玩梗/阴阳/锐评=中性，weibo 评论直球夸赞=正面。学生模型只看文本、无平台输入，只能靠文体特征（B站表情、回复格式）区分。**教训：口径规则必须按 (platform, content_type) 显式分片写进 teacher prompt，不能写全局规则。**

**坑 4（v5 试标）：跨口径信号泄漏。** 试标 weibo 150 条里博文仅 8 条、评论 142 条，评论的「直球夸赞→正面」信号把博文仪式应援带偏（博文 raw −2.7pt）。好在错误集中在低置信极化区，被 T0.75 回退全部吸收。修复：放量采样配额按三分片硬约束——B站评论 40% / weibo评论 30% / weibo博文 30%，候选行必须带 content_type 字段。

## 四、v6 踩坑：域内放量不等于提升，反而破坏安全网

**坑：** 用 LoL 赛事域新标 1000 条混训出 v6（6738 条），在 gold_eval_v4 上**全线低于 v5**（回退后 0.7756 vs 0.8097，配对净负 19，三片均败）；阈值扫描 T∈[0.6,0.9] 全区间劣于 v5 同阈值，无可用工作点。

**根因两条：**
1. **域偏移**：新数据集中在 LoL 单域，评估金标是多游戏混合（异环/鸣潮等）。单游戏域内放量不会带来跨域提升，反而让 B站中性短句更多误判为正面；
2. **置信度上移**：数据变多后模型更自信，max_prob<0.75 的样本从 149 条降到 60 条——低置信回退这张核心保护垫大幅缩水，raw 错误更多直达输出。

**结论**：下一轮候选池必须多游戏均衡采样；「数据多一点总没错」在蒸馏链路里不成立，先验对齐 > 数据量。

## 五、部署层实践：低置信回退的收益与代价

`infer_batch.py --conf_threshold 0.75`：softmax 最高概率 <0.75 改判中性（金标验证低置信样本约 76% 为中性），原始判定保留在 raw_sentiment 列供审计，低置信样本回流候选池滚动送标。

- **收益**：v5 总体 0.7576 → 0.8133（+5.6pt），B站 +13.3pt，正面召回不降；
- **代价一（负面召回）**：回退翻掉的 mostly 是真负面，实测负面召回 raw 11/20 → 回退后 6/20（30%）。若业务以负面监测为核心，需按片关闭或降低阈值；
- **代价二（分片不均）**：回退收益集中在 B站（玩梗歧义多、低置信极化），weibo 评论片回退净负（50 条抽检翻错 4 真负面仅翻对 1）；
- **边界**：回退只对低置信错误有效，conf≥0.75 的高置信错误（直球加油判中性 0.925、黑话反讽判正面 0.959）只能靠扩样本解决，已多次实证。

## 六、工程纪律（血泪换来的）

1. **改标签必须用 32 位完整 id 匹配**——8 位前缀匹配曾造成 262 条误翻；
2. **分片标注工作流**：teacher 判定写独立 jsonl，合并回候选原行时校验 id 集合 + text 逐字节一致，20+ 分片零返工；
3. **评估集版本化**：gold_eval_v4（557）上跑出的一切结论都绑死这个文件；新增金标另立 gold_eval_v5（857）不动旧集，历史数字永远可比；
4. **在 gold 上扫阈值 = 测试集调参**：v5 在 T0.85/0.90 数字更高，但必须新留出集确认才能改部署；
5. **金标内部也有噪声**：超短赞美/CP 转发链在金标里就不一致（「真好看」=正面 vs「好美😍」=中性），不要为了迁就模型做模式级标签翻转；
6. **版本对比规范**：三片准确率 + 配对差异（双对/仅A对/仅B对）+ 阈值扫描，杜绝小样本误判；
7. **合并新金标先查重合**：新 300 条 B站金标并入前扫描与训练集/候选池/旧金标 id 零重合（仅 1 条文本重合且标签一致），且这批 id 要加入下一轮候选排除集。
