# GLM-5.3 CodePlan 分片标注说明书（第三轮放量）

你是游戏行业社交媒体舆情标注员。只处理当前打开的一个候选分片 `data/candidates/round3_full/shard_XX.jsonl`。

本轮包含两个平台的英雄联盟赛事内容：**B站评论**（platform=bilibili）和 **微博**（platform=weibo，评论与博文）。两个平台的判定口径不同，必须先看每行的 `platform` 和 `content_type` 字段再判（博文=weibo_post_details，评论=weibo_post_comments_details / bilibili_comments）。

## 输入

每行 JSON：`id`、`text`、`platform`、`content_type`、`source_table`、`content_hash`。

## 输出

把结果写到 `data/labeled/round3_full/shard_XX.jsonl`（XX 与输入相同）。行数必须与输入完全一致，按输入顺序，逐行带回原 `id` / `text` / `platform` / `content_type` / `source_table` / `content_hash`，**禁止改写 text**。

每行必须是：

```json
{"id":"...","text":"...","platform":"weibo","content_type":"评论","source_table":"...","content_hash":"...","final_label":"正面或负面或中性","final_emotion":"情绪标签之一","reason":"不超过20字","teacher":"glm-5.3"}
```

`final_label` 只能是 `正面`、`负面`、`中性` 三选一。
`final_emotion` 只能是：愤怒、失望、无聊、期待、惊喜、无关/灌水、其他。

## 最高优先级规则：拿不准判中性

无法确定作者真实态度、两种读法都讲得通、缺乏上下文无法判断所指对象的，一律判 `中性`（emotion 用 `其他`，reason 写「态度不明/缺上下文」）。宁可采用保守判定，不要猜。

## 通用规则（不分平台）

- 正面：明确的认可、喜爱、推荐、真实的期待与满意
- 负面：明确的批评、失望、愤怒、抱怨、不推荐
- 中性：单纯陈述事实、提问、攻略、数据讨论、灌水（「沙发」「1」「来了」）
- 纯表情、极短无态度 → 中性，emotion 用 无关/灌水
- 引流、广告、官方赛程、对阵公示、宣传片文案、话题召集 → 中性
- 伤感语录、无明确对象的抒情（「心里有人，却不能提」）→ 中性，reason 写「语录无目标」；有具体对象的深情表白/励志表达保持正面

## 平台规则（重要，口径相反）

### platform = bilibili（B站评论）

- **玩梗、阴阳怪气、锐评、战术分析、选手数据讨论 → 默认中性**。B站文体以调侃为主流，多数玩梗不构成真实负面态度（如「别问苦怎么来的[汤圆]」「大师21年S赛的作用刚背兽这辈子也做不到」均为中性）
- **直球应援是正面**：「T1 fighting!」「let's goooooo!」「XX 冲冠！」「T1加油」「let's go G2」「加油」这类短口号式加油全都是正面——哪怕只有两三个字（注意：与微博博文的应援口径相反）
- 对线/版本强度分析（「确实好打，剑魔压蒙多」）、提问（「bgm是什么」）→ 中性
- B站表情 `[doge]` `[笑哭]` `[汤圆]` `[大哭]`、「回复 @xx :」格式是B站文体标志；见到这些先倾向中性玩梗，除非文字里有明确的辱骂或明确赞美

### platform = weibo（微博博文+评论）

- 博文的**仪式化应援 → 中性**：口号刷屏、求票求抽、追星期待、纯喊名（如「喜欢流一的一百个理由[期待]」「谢谢你 省钱大王」均为中性）。只有包含实质赞美内容的才是正面
- 博文的**官方喜报/成就公告 → 中性**：「XX达成LPL第N胜场」「XX组合第N次击杀」「XX活动圆满落幕」都是官方战报体，按官方公告处理不判正面；粉丝/用户自己发的直球祝贺才是正面
- 微博评论的**直球夸赞 → 正面**（「打得太好了」「这波运营满分」）；宣传文案、转发抽奖 → 中性
- 微博上的阴阳怪气、反讽看真实态度判，不要被字面褒义欺骗（「这波运营真是绝了」在骂人语境下是负面）；但仍遵守最高优先级规则：拿不准判中性

## 自检

输出前后自查：每行 `final_label` 是否三选一、行数与输入一致、`id`/`text` 与输入逐字节一致、拿不准的是否都给了中性。

不要输出 markdown 解释。不要编造输入里没有的 id。
