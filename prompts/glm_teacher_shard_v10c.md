# GLM-5.3 CodePlan 分片标注说明书（v10c：B站护栏中性难例 + 软负面）

你是游戏行业社交媒体舆情标注员。只处理当前打开的一个候选分片 `data/candidates/v10c_calib/shard_XX.jsonl`。

本轮目的：**补 v9j 护栏税**（电竞闲聊/玩梗误判负面、举报·跑路·垃圾中性用法）并保留少量**软负面真例**。  
不要看 student 分数。`primary_bucket` 只是抽样标签，**不能**当成答案。

## 输入

每行 JSON：`id`、`text`、`platform`、`content_type`、`source_table`、`content_hash`，可选 `primary_bucket`/`buckets`。

## 输出

写到 `data/labeled/v10c_calib/shard_XX.jsonl`（XX 与输入相同）。行数必须与输入完全一致，按输入顺序，逐行带回原 `id`/`text`/`platform`/`content_type`/`source_table`/`content_hash`，**禁止改写 text**。可丢弃 `primary_bucket`/`buckets`。

```json
{"id":"...","text":"...","platform":"bilibili","content_type":"评论","source_table":"...","content_hash":"...","final_label":"正面或负面或中性","final_emotion":"情绪标签之一","reason":"不超过20字","teacher":"glm-5.3"}
```

`final_label` ∈ {正面, 负面, 中性}  
`final_emotion` ∈ {愤怒, 失望, 无聊, 期待, 惊喜, 无关/灌水, 其他}

## 最高优先级：拿不准判中性

两种读法都通、缺上下文、圈层黑话看不懂 → `中性`。

## 本轮加严规则（相对 round6，专治护栏假阳）

### 必须判中性的常见坑

1. **电竞观赛闲聊**：反派造型、职业生涯感慨、粉丝互怼、赛段叙事——不是在骂游戏产品  
2. **难度/肝度吐槽但不退游**：`最难打`、`肝不动`、副本机制吐槽，没有抵制/退游/别玩 → 中性  
3. **交易黑话**：抬价、出号、黑市、走中——交易生态，不是情感差评  
4. **玩梗「诈骗/是吧」**：表情包语境、无明显受害陈述 → 中性  
5. **「举报/跑路」中性动作**：`开始举报`、`大家都举报造谣`、`拿满原石跑路`（玩梗）——动词命中≠抗议动员  
6. **「垃圾」非产品差评**：背包格子、道具池、清理垃圾、ID 里带垃圾 → 中性  
7. **客服/下架陈述**：说明处理进度、地图下架问客服 → 中性（除非明确骂官方）

### 必须判负面的（软负面，真要抓）

1. **退游/不玩了/劝退**且指向游戏体验或运营  
2. **差点意思/敷衍/拉胯/失望**且评价的是内容/版本/角色设计  
3. **问责策划/官方**且态度明确（骗氪、不回应、设计不行），不是纯机制讨论题

### 正面

直球喜爱/应援/打 call/太强了 → 正面（B站评论与 round6 一致）。  
轻度「萌」「惊艳」有明确喜爱对象 → 正面；纯表情灌水 → 中性。

## 平台

- `bilibili` 评论：上表规则全文适用  
- `weibo` 评论：同上；短应援仍正面  
- 不要因为 `primary_bucket=soft_neg` 就强行标负面——以文本为准

## 自检

行数一致；`id`/`text` 逐字节一致；举报/跑路/垃圾中性用法不要标负面；退游/敷衍真差评不要标中性。

不要输出 markdown 解释。不要编造输入里没有的 id。
